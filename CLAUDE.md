# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Static marketing website for **Saint-Gratien FC**, a football club for kids in Saint-Gratien (Val-d'Oise, France), founded in 2020 — this is its first structured season. Plain HTML/CSS/JS, no build tools, no framework, no package manager. Files are served as-is; edit them directly and refresh the browser.

## Running locally

There is no dev server, build, lint, or test command configured. To preview the site, serve the folder root with any static file server, e.g.:

```
python -m http.server 8000
```

Then open `http://localhost:8000/index.html`.

## Architecture

- **6 standalone HTML pages**, no templating engine: `index.html`, `actualites.html`, `equipe.html`, `entrainements.html`, `partenaires.html`, `contact.html`. Each page duplicates the same `<header>` and `<footer>` markup verbatim — when changing nav links, social links, or footer contact info, apply the edit to **all 6 files**.
- **`assets/css/styles.css`**: single stylesheet. Design tokens (colors, fonts, spacing) are CSS custom properties in `:root`, with the color palette sampled directly from the club crest (maroon/gold/cream/red). Reusable component classes: `.card`, `.info-list`/`.info-item`, `.cta-banner`, `.eyebrow`, `.filters`/`.filter-btn`. **Premium polish pass (2026-07-21)**: `.btn-primary`/`.btn-dark` use a background-image gradient sweep for a hover "shine" (no pseudo-element, so button text is never at risk of being covered by z-index issues — keep that pattern for any new solid-fill button variant); `.page-header` now mirrors the `.hero`'s diagonal-stripe + radial-glow pattern via `::before`/`::after` for visual cohesion; `.eyebrow::before` has a subtle pulsing dot animation; `.info-item .icon` is a soft gradient badge sized for inline SVG (`.icon svg` at 21px) — **all emoji icons were replaced with hand-written line-icon SVGs** (stroke-width 1.8, viewBox 0 0 24 24) for a consistent, non-emoji look; only `partenaires.html`'s numbered `1`–`4` badges remain as plain text by design.
- **`assets/js/main.js`**: vanilla JS, no dependencies. Key behaviors: sticky header shrink-on-scroll, mobile nav toggle, scroll-reveal via `IntersectionObserver` (elements with `[data-reveal]`), neutralizing placeholder `href="#"` links, and an article "lightbox" (clicking a news `article.card` opens it enlarged in a modal — `#article-lightbox`, present on `index.html` and `actualites.html` only; dormant now that real articles link to their own page instead, see below — kept for backward compat, no-ops safely with the dynamically-injected cards since `initArticleLightbox`/`initNewsFilters` run at `DOMContentLoaded`, before `actualites.js`'s async fetch populates the grid). News category filters used to live here (`data-filter`/`data-category`) but as of 2026-09-03 that logic moved to `assets/js/actualites.js` (see the "Actualités (Sveltia CMS)" section below) since the cards are now rendered dynamically, not static markup.
- **Actualités (Sveltia CMS), added 2026-09-03**: the club publishes news itself from `/admin` (Sveltia CMS, https://github.com/sveltia/sveltia-cms — a modern Decap/Netlify CMS-compatible fork) instead of asking for a Claude Code session each time.
  - **Content storage**: a single `content/articles.json` (`{"articles": [...]}`), edited via `admin/config.yml`'s one "files" collection with a `list` field. Fields per article: `title`, `date`, `category` (one of `club`/`inscriptions`/`benevolat`/`evenement`/`partenariat` — keep these 5 values in sync across `admin/config.yml`, `assets/js/actualites.js`'s `CATEGORY_LABELS`/`CATEGORY_ICONS`, and `functions/actualites/[slug].js`'s copies of the same maps, plus the static filter buttons in `actualites.html`), `slug` (used in the article URL, lowercase/hyphens only), `excerpt`, `body` (plain text, paragraphs separated by a blank line — no Markdown renderer, consistent with the no-build-step project philosophy), `image` (optional, uploaded to `assets/images/actualites/`).
  - **Rendering**: `assets/js/actualites.js` fetches `content/articles.json` client-side and injects cards into `#actualites-grid` on both `actualites.html` (full grid + filters, `#actualites-filters`) and `index.html` (latest 3, `data-limit="3"` on the grid, no filters). Both pages keep their original "bientôt disponible" block, now `hidden` by default and only shown by the script when the articles array is empty.
  - **Real per-article pages (SEO)**: `functions/actualites/[slug].js` is a Pages Function that reads `content/articles.json` (via the `env.ASSETS.fetch` binding, always available to Pages Functions with no extra config) and server-renders a full HTML page per article (proper `<title>`/meta description/OG tags, header/footer duplicated like every other page) — this fulfills the SEO goal noted below (a real indexable page per article, not just a teaser). Unknown slugs return a real **404** (reusing `404.html`, fixed 2026-09-03 — a 302 redirect to `actualites.html` was a "soft 404" Google discourages). Card titles and the "Lire la suite" links in `actualites.js` point here.
  - **Auth**: Sveltia can't keep a GitHub OAuth client secret in the browser, so `functions/auth.js` + `functions/callback.js` (sharing helpers in `functions/_shared/oauth-common.js`, excluded from Pages routing by the `_` prefix) implement the OAuth relay — adapted **GitHub-only** from the official [`sveltia-cms-auth`](https://github.com/sveltia/sveltia-cms-auth) Cloudflare Worker (MIT), ported to Pages Functions of *this* project instead of a separate Worker, so it ships with the same `git push` deploy and the same Cloudflare Pages dashboard used for the `INSCRIPTION_STATUS` KV binding. Requires these Cloudflare Pages environment variables (set once via the dashboard, never committed): `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` (a GitHub OAuth App with callback URL `https://saintgratienfc.fr/callback`), and `ALLOWED_DOMAINS=saintgratienfc.fr`. **Known gotcha fixed 2026-09-03**: the original English error strings had no apostrophes, so the source concatenated the `postMessage` payload inside a single-quoted JS string literal; the French error messages here do contain apostrophes ("L'identifiant…") which broke that literal — fixed by building the message via `JSON.stringify`/`serialize()` instead of raw interpolation (see `outputHTML` in `oauth-common.js`). Any new/edited error string must stay ASCII-quote-safe through that same path.
  - **CSP**: `_headers`' single `/*` Content-Security-Policy rule was widened for `/admin` (added `https://unpkg.com` to `script-src`/`connect-src`, `https://api.github.com` to `connect-src`, `https://cdn.jsdelivr.net` to `font-src`, `blob:`/`data:` to several directives, `https://avatars.githubusercontent.com` to `img-src`) — applied site-wide since only the blanket `/*` rule reliably applies here (see the Cloudflare Pages quirk noted below), but only exercised in practice by `/admin`.
- **`assets/images/`**: `logo.png` (club crest, optimized down from a ~4MB original), `favicon.ico` generated from it, and `og-image.jpg` (1200×630 social-share preview — maroon gradient + diagonal stripes + crest, rendered 2026-07-21 to match the hero's exact look; referenced by every page's `og:image`/`twitter:image`, with `twitter:card` set to `summary_large_image`). To regenerate it: build a temp HTML page styled like `.hero` sized to a 1200×630 `<div>`, screenshot/crop it, then delete the temp file — don't leave scratch render files in the repo.
- **Domain**: `saintgratienfc.fr`, registered 2026-08-31 at **Infomaniak** (registrar only — DNS to be delegated to Cloudflare; hosting stays Cloudflare Pages). `sitemap.xml`, `robots.txt`, and every HTML page's `<link rel="canonical">` and Open Graph/Twitter tags were updated from the old `votre-domaine.fr` placeholder to `https://saintgratienfc.fr` on 2026-08-31. **Note: `saintgratien.fr` (without `fc`) is NOT ours** — it belongs to the company DATAXY (registered 2004) and redirects to a private commercial local directory; never use it in canonicals, OG tags, or docs. The site is **live** at this domain (Cloudflare Pages project `saintgratienfc`, auto-deploys on push to `main`).
- **`_headers`** (root): security headers (CSP, HSTS, X-Frame-Options, Referrer-Policy, Permissions-Policy) applied via a `/*` rule. **Cloudflare Pages ignores `_headers` rules more specific than `/*` for static asset paths** (verified 2026-08-31 by deploying a rule scoped to `/assets/js/main.js` with a custom test header — it never appeared, not even for non-reserved header names) — don't rely on per-path `_headers` rules for assets; only the blanket `/*` rule reliably applies.
- **Cache-busting for `assets/js/main.js`, `assets/js/inscription.js`, `assets/js/actualites.js`, `assets/css/styles.css`**: Cloudflare Pages sets `Cache-Control: max-age=14400` (4h) on these by default, and that can't be overridden via `_headers` (see above). Every HTML page references them with a manual `?v=YYYYMMDD` query string (e.g. `assets/js/main.js?v=20260831`) — **bump this version string on every edit to these files** (find/replace across all HTML files), otherwise returning visitors can run stale JS/CSS for up to 4 hours after a deploy. This caused a real incident on 2026-08-31: a JS fix (inscription/HelloAsso buttons) was live on the server but a browser kept executing the cached pre-fix `main.js`, making the fix look like it hadn't worked.
- **`functions/CLAUDE.md.js`** and **`functions/status.json.js`**: block public access (404) to `CLAUDE.md` and `status.json`, which otherwise get deployed and served publicly since the repo root is the Pages build output with no build step. Pages Functions take priority over same-named static assets (unlike `_redirects`, which does **not** override an existing static file — tried that first, it silently didn't work).
- **Inscriptions (base D1), added 2026-09-03**: `inscription.html`'s form also POSTs to `functions/api/inscriptions.js`, which stores each submission in a Cloudflare **D1** database (binding `DB`, database `saintgratienfc-inscriptions`, created with **EU jurisdiction** — matches the claim in `confidentialite.html` that data stays in Europe, don't create a replacement DB without the same jurisdiction). The table (`inscriptions`) is created/migrated on first use via `CREATE TABLE IF NOT EXISTS` + a loop of best-effort `ALTER TABLE ADD COLUMN` (duplicate-column errors swallowed) in `functions/_shared/inscriptions-db.js` (shared by every read/write Function) — no manual migration step for the user, new columns just get added here as the feature grows. **This call is no longer purely best-effort/fire-and-forget** (it was until 2026-09-04): the client now `await`s the response (see `assets/js/inscription.js`) because the JSON reply carries `uploadToken`, needed to build the signed-document deposit link (see below) — a failed request still degrades gracefully (falls back to a mailto link) but no longer happens silently in the background.
  - **Consultation**: `functions/admin/inscriptions.js` renders a responsive card grid (`repeat(auto-fill, minmax(300px,1fr))` — deliberately not a `<table>`, which forced horizontal scrolling on desktop too, not just mobile) behind a shared-password gate — `ADMIN_PASSWORD` (Cloudflare Pages secret, set by the user, never committed) compared against an `admin_auth` cookie (`HttpOnly; Secure; SameSite=Lax`, scoped to `/admin`), auth logic centralized in `functions/_shared/admin-auth.js` (`isAuthed`/`loginPage`/`escapeHtml`/`COOKIE_NAME`) so every admin page (list, edit, dossier download) shares one implementation. Deliberately simple (no session store, no hashing) — proportionate to a single-shared-password internal tool, not a multi-user auth system.
  - **Filtres/tri (2026-09-04)**: search (nom/prénom/e-mail), catégorie, année de naissance (dérivée dynamiquement des données, pas codée en dur — les années changent chaque saison), mode de paiement, statut du dossier signé, et un tri (date/nom A↔Z/naissance) — tous en query params GET, filtrage/tri fait côté JS après un `SELECT *` (peu de lignes attendues pour un seul club, plus simple et plus sûr qu'une clause `WHERE` dynamique). L'export CSV respecte les filtres actifs.
  - **Édition/suppression (2026-09-04)**: `functions/admin/inscriptions/[id].js` (GET affiche un formulaire pré-rempli, POST enregistre) et une suppression via `onRequestPost` de `inscriptions.js` (`action=delete` dans le même formulaire POST que le login, distingué par ce champ cible). Cloudflare Pages route correctement le fichier `inscriptions.js` (`/admin/inscriptions`) et le dossier `inscriptions/` (`/admin/inscriptions/:id`, `/admin/inscriptions/:id/dossier`) côte à côte, sans collision.
  - **Escaping**: chaque page admin doit rester disciplinée sur l'échappement HTML (`escapeHtml`) de tout champ soumis par le public avant affichage — `naissance` a en plus une validation de format côté API (`^\d{4}-\d{2}-\d{2}$`) depuis que les années qu'il contient alimentent, non échappées à l'origine, le filtre "année de naissance" (trou XSS potentiel comblé le 2026-09-04, `y` est maintenant aussi passé par `escapeHtml` par sécurité en profondeur).
  - **Jersey size (`tailleMaillot`)**: a required `<select>` in `inscription.html` (options `4 ans`/`6 ans`/`8 ans`/`10 ans`/`12 ans`, French kids' clothing sizing) — included in the generated PDF (`generatePdf()` in `inscription.js`).
  - **Mode de paiement + widget HelloAsso embarqué (2026-09-04)**: un `<select>` requis `modePaiement` (`HelloAsso`/`Espèces`/`Chèque`) conditionne l'étape 2 du parcours — si HelloAsso, un widget de paiement est **embarqué en iframe** directement sur `inscription.html` (`createHelloAssoWidget()` dans `inscription.js`) plutôt qu'un lien externe, pour que le parent ne quitte pas le site. Deux widgets (un par campagne HelloAsso, U6-U7/U8-U9), URLs fournies par le club depuis son dashboard HelloAsso (onglet "Diffuser → Bouton & widget") — format : même chemin que le lien de paiement classique mais **sans le préfixe `/beta`** et avec `/widget` en suffixe. Nécessite `frame-src https://www.helloasso.com` et `Permissions-Policy: payment=(self "https://www.helloasso.com")` dans `_headers`.

## Responsive

- `.grid-2` collapses to 1 column at **760px** (not 620px like `.grid-3`/`.grid-4`) — deliberately split in the `@media` rules so 2-column text+content sections (mission/encadrement, catégories, contreparties, etc.) don't get squeezed into narrow columns on tablets before stacking. Don't recombine that rule with `.grid-3`/`.grid-4` without re-checking nested-grid sections like index.html's "Un club, des valeurs".
- All `.btn` use `white-space: nowrap` — keep button labels short (≲25 chars); a longer label can overflow its column on narrow screens instead of wrapping. Fixed one real instance on 2026-07-21 (index.html partners CTA, was "Découvrir le dossier de sponsoring" → "Découvrir le dossier").
- **Tooling note**: `mcp__claude-in-chrome__resize_window` does not actually resize the browser viewport in this dev environment (confirmed via `window.innerWidth` staying at the real window size regardless of the requested width) — don't rely on it for visual mobile QA here; audit responsive behavior by reading the CSS media queries against each page's markup instead. Also, a long-lived tab caches `assets/css/styles.css` aggressively across navigations in this session — after editing the CSS, bust the cache (reset the `<link>` `href` with a `?bust=` query, or re-fetch with `cache:'no-store'`) before trusting `getComputedStyle` results, otherwise you'll be testing stale rules.
- **Fixed 2026-07-21**: `.site-header` had `backdrop-filter: blur(10px)`, which (like `transform`/`filter`/`perspective`/`will-change`) makes an element a new containing block for `position: fixed` descendants. Since `.main-nav` (the mobile slide-in menu) is `position: fixed` *inside* `.site-header`, its `inset: var(--header-h) 0 0 0` was resolving against the ~84px-tall header instead of the viewport — collapsing the panel to 0 height (menu opened but showed nothing). Removed `backdrop-filter` from `.site-header` to fix; confirmed via `getBoundingClientRect` before/after (0px → 626px). If a header blur effect is wanted again, put it on a `::before` pseudo-element instead of the header itself, never on an ancestor of the fixed nav.
- **Fixed 2026-07-21**: `.hero-crest img` had `width="360" height="360"` HTML attributes, but CSS only overrode `width: min(360px, 80%)` — `height` fell back to the fixed `360px` attribute on narrow screens, stretching the crest vertically. Added `height: auto` to `.hero-crest img`.

## Project-specific conventions

- Only add a "Lire la suite" / read-more link to a news card if there is genuinely more content behind it (a real detail page). As of 2026-09-03 this is true for every article (see "Actualités (Sveltia CMS)" above): `assets/js/actualites.js` always adds this link, pointing at the `functions/actualites/[slug].js`-rendered page.
- SEO rationale for news articles, now implemented: each published article gets its own indexable page (`functions/actualites/[slug].js`), not just a lightbox teaser — more pages on the site means more entry points Google can index.
- The footer "Newsletter" signup form is intentionally non-functional (`onsubmit` just calls `preventDefault()`, no backend) — it's a placeholder kept for future use at the user's request; don't remove it during cleanup passes.
