# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Static marketing website for **Saint-Gratien FC**, a football club for kids in Saint-Gratien (Val-d'Oise, France), founded in 2020 — this is its first structured season. Plain HTML/CSS/JS, no build tools, no framework, no package manager. Files are served as-is; edit them directly and refresh the browser.

## Running locally

There is no build step or configured dev server. Run `npm run check` to verify asset references and execute the Node tests (Node 24 supported, including `node:sqlite`). The tests use SQLite in memory and mocked external services. To preview the static pages, serve the folder root with any static file server, e.g.:

```
python -m http.server 8000
```

Then open `http://localhost:8000/index.html`.

## Architecture

- **6 standalone HTML pages**, no templating engine: `index.html`, `actualites.html`, `equipe.html`, `entrainements.html`, `partenaires.html`, `contact.html`. Each page duplicates the same `<header>` and `<footer>` markup verbatim — when changing nav links, social links, or footer contact info, apply the edit to **all 6 files**.
- **`assets/css/styles.css`**: single stylesheet. Design tokens (colors, fonts, spacing) are CSS custom properties in `:root`, with the color palette sampled directly from the club crest (maroon/gold/cream/red). Reusable component classes: `.card`, `.info-list`/`.info-item`, `.cta-banner`, `.eyebrow`, `.filters`/`.filter-btn`. **Premium polish pass (2026-07-21)**: `.btn-primary`/`.btn-dark` use a background-image gradient sweep for a hover "shine" (no pseudo-element, so button text is never at risk of being covered by z-index issues — keep that pattern for any new solid-fill button variant); `.page-header` now mirrors the `.hero`'s diagonal-stripe + radial-glow pattern via `::before`/`::after` for visual cohesion; `.eyebrow::before` has a subtle pulsing dot animation; `.info-item .icon` is a soft gradient badge sized for inline SVG (`.icon svg` at 21px) — **all emoji icons were replaced with hand-written line-icon SVGs** (stroke-width 1.8, viewBox 0 0 24 24) for a consistent, non-emoji look; only `partenaires.html`'s numbered `1`–`4` badges remain as plain text by design. **Header aligné sur l'admin (2026-09-15)**, à la demande de l'utilisateur : `.site-header` reprend la barre `.adm-topnav` (dégradé bordeaux + halo or, rayures fines sur `::before`, liens en pastille Inter non capitalisés, page active = fond blanc 15 % + soulignement or ; menu mobile : barre or à gauche). CSS seul, le HTML dupliqué des pages n'a pas changé. Les styles de liens ciblent `.main-nav li a` (pas `.main-nav a`, qui écrasait couleur et marges du bouton `.nav-cta` du menu mobile). Entre 881 et 1100px, le sous-titre "Val-d'Oise" est masqué et les pastilles resserrées, sinon le nom du club passait sur 3 lignes. Même passe : `#actualites-grid` utilise `.news-grid` (flex centré, pas `.grid-3`, pour qu'1 ou 2 cartes ne laissent pas une colonne vide) ; la carte Google Maps (`.map-embed` > `.map-placeholder`, sur `contact.html`/`inscription.html`/`entrainements.html`) n'a plus de styles en ligne — le cadre prend la hauteur de son contenu (épingle, adresse, bouton, lien "Ouvrir dans Google Maps") et c'est l'iframe insérée au clic qui porte le ratio (`.map-embed--wide` = 16/9).
- **`assets/js/main.js`**: vanilla JS, no dependencies. Key behaviors: sticky header shrink-on-scroll, mobile nav toggle, scroll-reveal via `IntersectionObserver` (elements with `[data-reveal]`), neutralizing placeholder `href="#"` links, and an article "lightbox" (clicking a news `article.card` opens it enlarged in a modal — `#article-lightbox`, present on `index.html` and `actualites.html` only; dormant now that real articles link to their own page instead, see below — kept for backward compat, no-ops safely with the dynamically-injected cards since `initArticleLightbox`/`initNewsFilters` run at `DOMContentLoaded`, before `actualites.js`'s async fetch populates the grid). News category filters used to live here (`data-filter`/`data-category`) but as of 2026-09-03 that logic moved to `assets/js/actualites.js` (see the "Actualités (Sveltia CMS)" section below) since the cards are now rendered dynamically, not static markup.
- **Actualités (Sveltia CMS), added 2026-09-03**: the club publishes news itself from `/admin` (Sveltia CMS, https://github.com/sveltia/sveltia-cms — a modern Decap/Netlify CMS-compatible fork) instead of asking for a Claude Code session each time.
  - **Content storage**: a single `content/articles.json` (`{"articles": [...]}`), edited via `admin/config.yml`'s one "files" collection with a `list` field. Fields per article: `title`, `date`, `category` (one of `club`/`inscriptions`/`benevolat`/`evenement`/`partenariat` — keep these 5 values in sync across `admin/config.yml`, `assets/js/actualites.js`'s `CATEGORY_LABELS`/`CATEGORY_ICONS`, and `functions/actualites/[slug].js`'s copies of the same maps, plus the static filter buttons in `actualites.html`), `slug` (used in the article URL, lowercase/hyphens only), `excerpt`, `body` (plain text, paragraphs separated by a blank line — no Markdown renderer, consistent with the no-build-step project philosophy), `image` (optional, uploaded to `assets/images/actualites/`).
  - **Rendering**: `assets/js/actualites.js` fetches `content/articles.json` client-side and injects cards into `#actualites-grid` on both `actualites.html` (full grid + filters, `#actualites-filters`) and `index.html` (latest 3, `data-limit="3"` on the grid, no filters). Both pages keep their original "bientôt disponible" block, now `hidden` by default and only shown by the script when the articles array is empty.
  - **Real per-article pages (SEO)**: `functions/actualites/[slug].js` is a Pages Function that reads `content/articles.json` (via the `env.ASSETS.fetch` binding, always available to Pages Functions with no extra config) and server-renders a full HTML page per article (proper `<title>`/meta description/OG tags, header/footer duplicated like every other page) — this fulfills the SEO goal noted below (a real indexable page per article, not just a teaser). Unknown slugs return a real **404** (reusing `404.html`, fixed 2026-09-03 — a 302 redirect to `actualites.html` was a "soft 404" Google discourages). Card titles and the "Lire la suite" links in `actualites.js` point here.
  - **Auth**: Sveltia can't keep a GitHub OAuth client secret in the browser, so `functions/auth.js` + `functions/callback.js` (sharing helpers in `functions/_shared/oauth-common.js`, excluded from Pages routing by the `_` prefix) implement the OAuth relay — adapted **GitHub-only** from the official [`sveltia-cms-auth`](https://github.com/sveltia/sveltia-cms-auth) Cloudflare Worker (MIT), ported to Pages Functions of *this* project instead of a separate Worker, so it ships with the same `git push` deploy and the same Cloudflare Pages dashboard used for the `INSCRIPTION_STATUS` KV binding. Requires these Cloudflare Pages environment variables (set once via the dashboard, never committed): `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` (a GitHub OAuth App with callback URL `https://saintgratienfc.fr/callback`), and `ALLOWED_DOMAINS=saintgratienfc.fr`. **Known gotcha fixed 2026-09-03**: the original English error strings had no apostrophes, so the source concatenated the `postMessage` payload inside a single-quoted JS string literal; the French error messages here do contain apostrophes ("L'identifiant…") which broke that literal — fixed by building the message via `JSON.stringify`/`serialize()` instead of raw interpolation (see `outputHTML` in `oauth-common.js`). Any new/edited error string must stay ASCII-quote-safe through that same path.
  - **CSP**: `_headers`' single `/*` Content-Security-Policy rule was widened for `/admin` (added `https://unpkg.com` to `script-src`/`connect-src`, `https://api.github.com` to `connect-src`, `https://cdn.jsdelivr.net` to `font-src`, `blob:`/`data:` to several directives, `https://avatars.githubusercontent.com` to `img-src`) — applied site-wide since only the blanket `/*` rule reliably applies here (see the Cloudflare Pages quirk noted below), but only exercised in practice by `/admin`. **2026-09-15** : `https://challenges.cloudflare.com` ajouté à `script-src` et `frame-src` pour Cloudflare Turnstile (formulaire d'inscription).
- **`assets/images/`**: `logo.png` (club crest, optimized down from a ~4MB original), `favicon.ico` generated from it, and `og-image.jpg` (1200×630 social-share preview — maroon gradient + diagonal stripes + crest, rendered 2026-07-21 to match the hero's exact look; referenced by every page's `og:image`/`twitter:image`, with `twitter:card` set to `summary_large_image`). - **Raccourci écran d'accueil mobile (PWA légère), ajouté 2026-09-09**: **deux manifestes séparés**, pas un seul — `manifest.json` (racine, blason, `start_url: "/"`, `scope: "/"`) pour le site public, et `manifest-admin.json` (même blason depuis le 2026-09-15, `start_url: "/admin/dashboard"`, `scope: "/admin"`) pour la partie admin. **Raison** : un seul manifest avec `start_url: "/"` fait qu'un admin qui installe l'app depuis `/admin/inscriptions` se retrouve à rouvrir la page d'accueil du site, pas l'admin — Chrome/Android lance toujours `start_url` du manifest à l'ouverture d'une app installée, jamais la page depuis laquelle on a lancé l'installation. Chaque page du site charge l'un ou l'autre selon son contexte (`/manifest.json` sur les 10 pages publiques + les pages à jeton `/depot`, `/reinscription` ; `/manifest-admin.json` sur `/admin/*` — CMS Sveltia inclus — et `functions/_shared/admin-auth.js`/chaque `functions/admin/*.js`), jamais les deux à la fois sur une même page.
  - **Icônes** : un seul jeu, le **blason du club, partout** (demande de l'utilisateur le 2026-09-15 : l'app admin installée sur téléphone affichait un cadenas) — `assets/images/favicon.ico`, `assets/images/icons/icon-{192,512,maskable-512}.png` (fond `--maroon-900` `#4f1414`) et `assets/images/apple-touch-icon.png`, référencés par les deux manifestes, les pages publiques, `inscription.html` (qui avait son propre favicon), `adminHead()` et le CMS `admin/index.html`. Les anciennes icônes cadenas (`favicon-admin.*`, `icon-admin-*`, `apple-touch-icon-admin.png`) et `favicon-inscription.*` ont été supprimées. Les PNG ont été générés via un `<canvas>` dans Chrome (pas de conversion webp→png disponible en CLI ici, cf. `og-image.jpg`). Une app déjà installée garde son ancienne icône : la désinstaller puis la réinstaller.
  - Pas de service worker (pas d'usage hors-ligne visé) : juste `<link rel="manifest">`/`apple-touch-icon` + `theme-color`/`mobile-web-app-capable` sur chaque page. `display: "standalone"` dans les deux manifests donne un rendu façon appli (sans barre d'adresse) à l'ouverture depuis l'icône.

- **`_headers`** (root): security headers (CSP, HSTS, X-Frame-Options, Referrer-Policy, Permissions-Policy) applied via a `/*` rule. **Cloudflare Pages ignores `_headers` rules more specific than `/*` for static asset paths** (verified 2026-08-31 by deploying a rule scoped to `/assets/js/main.js` with a custom test header — it never appeared, not even for non-reserved header names) — don't rely on per-path `_headers` rules for assets; only the blanket `/*` rule reliably applies.
- **Versions des assets (cache 4h de Cloudflare Pages)** : `assets/css/*` et `assets/js/*` sont servis avec `Cache-Control: max-age=14400`, non modifiable via `_headers` (voir ci-dessus). Chaque référence porte donc `?v=<empreinte>` — **ne plus les modifier à la main : lancer `npm run sync`** (`scripts/sync-assets.mjs`, depuis 2026-09-15) après toute modification d'un fichier de `assets/css` ou `assets/js`. Le script calcule l'empreinte de chaque fichier et met à jour les pages HTML et les Functions, règle `ASSETS_VERSION` (`functions/_shared/admin-auth.js`, utilisé par `adminHead()`/`adminScripts()` pour toutes les pages admin) sur l'empreinte de l'ensemble, et recopie le header/footer d'`index.html` dans les autres pages s'ils ont divergé. `npm run check` vérifie sans rien écrire, puis lance les tests. Incident d'origine (2026-08-31) : un correctif JS en ligne paraissait inopérant parce qu'un navigateur exécutait encore l'ancien `main.js` en cache.
- **`functions/CLAUDE.md.js`** and **`functions/status.json.js`**: block public access (404) to `CLAUDE.md` and `status.json`, which otherwise get deployed and served publicly since the repo root is the Pages build output with no build step. Pages Functions take priority over same-named static assets (unlike `_redirects`, which does **not** override an existing static file — tried that first, it silently didn't work).
- **Inscriptions (base D1), added 2026-09-03**: `inscription.html`'s form also POSTs to `functions/api/inscriptions.js`, which stores each submission in a Cloudflare **D1** database (binding `DB`, database `saintgratienfc-inscriptions`, created with **EU jurisdiction** — matches the claim in `confidentialite.html` that data stays in Europe, don't create a replacement DB without the same jurisdiction). The table (`inscriptions`) is created/migrated on first use via `CREATE TABLE IF NOT EXISTS`, schema inspection (`PRAGMA table_info`) and a transactional D1 `batch` for missing columns, backfills and indexes (real errors propagate; a concurrent column addition triggers one schema reread) in `functions/_shared/inscriptions-db.js` (shared by every read/write Function) — no manual migration step for the user, new columns just get added here as the feature grows. **This call is no longer purely best-effort/fire-and-forget** (it was until 2026-09-04): the client now `await`s the response (see `assets/js/inscription.js`) because the JSON reply carries `uploadToken`, needed to build the signed-document deposit link (see below) — a failed request still degrades gracefully (falls back to a mailto link) but no longer happens silently in the background.

## Responsive

- `.grid-2` collapses to 1 column at **760px** (not 620px like `.grid-3`/`.grid-4`) — deliberately split in the `@media` rules so 2-column text+content sections (mission/encadrement, catégories, contreparties, etc.) don't get squeezed into narrow columns on tablets before stacking. Don't recombine that rule with `.grid-3`/`.grid-4` without re-checking nested-grid sections like index.html's "Un club, des valeurs".
- All `.btn` use `white-space: nowrap` — keep button labels short (≲25 chars); a longer label can overflow its column on narrow screens instead of wrapping. Fixed one real instance on 2026-07-21 (index.html partners CTA, was "Découvrir le dossier de sponsoring" → "Découvrir le dossier").
- **Tooling note**: `mcp__claude-in-chrome__resize_window` does not actually resize the browser viewport in this dev environment (confirmed via `window.innerWidth` staying at the real window size regardless of the requested width) — don't rely on it for visual mobile QA here; audit responsive behavior by reading the CSS media queries against each page's markup instead. Also, a long-lived tab caches `assets/css/styles.css` aggressively across navigations in this session — after editing the CSS, bust the cache (reset the `<link>` `href` with a `?bust=` query, or re-fetch with `cache:'no-store'`) before trusting `getComputedStyle` results, otherwise you'll be testing stale rules.
- **Fixed 2026-07-21**: `.site-header` had `backdrop-filter: blur(10px)`, which (like `transform`/`filter`/`perspective`/`will-change`) makes an element a new containing block for `position: fixed` descendants. Since `.main-nav` (the mobile slide-in menu) is `position: fixed` *inside* `.site-header`, its `inset: var(--header-h) 0 0 0` was resolving against the ~84px-tall header instead of the viewport — collapsing the panel to 0 height (menu opened but showed nothing). Removed `backdrop-filter` from `.site-header` to fix; confirmed via `getBoundingClientRect` before/after (0px → 626px). If a header blur effect is wanted again, put it on a `::before` pseudo-element instead of the header itself, never on an ancestor of the fixed nav.
- **Fixed 2026-07-21**: `.hero-crest img` had `width="360" height="360"` HTML attributes, but CSS only overrode `width: min(360px, 80%)` — `height` fell back to the fixed `360px` attribute on narrow screens, stretching the crest vertically. Added `height: auto` to `.hero-crest img`.

## Fiabilité des inscriptions (2026-09-16)

- Le POST d'inscription utilise `INSERT ... SELECT ... WHERE NOT EXISTS` : la vérification finale du doublon et l'insertion sont atomiques, même après deux pré-vérifications simultanées. La clé comprend l'identité normalisée, la naissance et la saison. Les doublons historiques restent conservés.
- Les dates doivent exister dans le calendrier et ne pas être futures ; les tailles et modes de paiement sont contrôlés côté serveur.
- Les migrations sont mises en cache par binding D1. Les remplissages idempotents réparent les saisons, statuts et clés de déduplication absents après une ancienne migration incomplète.
- HelloAsso réserve la commande, applique les paiements encore éligibles et enregistre le résultat dans un même `DB.batch`. Les notifications sont déclenchées après validation de la transaction. Leur envoi reste best-effort, sans file persistante de reprise.
